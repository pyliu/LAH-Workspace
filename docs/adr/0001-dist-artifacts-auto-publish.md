# 0001: 打包成品自動增量發布至開發機發布資料夾

**狀態**: 已採納 (Accepted)  
**日期**: 2026-11-02  

### 決策背景與脈絡
每次完成智慧控管與監控系統之打包後，維運人員需手動將 `LAH-Updater/dist/` 下的打包成品複製至開發機之發布目錄（`d:\DEV\@各所分享區\@智慧管控系統\@更新程式\<版號>`），以供本機排程定時同步至公用 NAS。人工複製容易發生遺漏單檔、誤複製截圖（如 `*.jpg`）或版號資料夾拼寫不一致之問題。

### 決策內容與原因
在 `LAH-Updater/pack/pack.py` 打包流程的最後一步整合自動複製機制：
1. **版號動態綁定**：以 `LAH-FE/package.json` 中的 `version` 欄位為單一真實來源（Single Source of Truth），自動加上 `v` 前綴建立目的端版號資料夾（如 `v1.9.9`）。
2. **成品白名單過濾**：僅複製副檔名為 `*.txt`, `*.pdf`, `*.exe`, `*.zip` 的成品，排除操作截圖（`*.jpg`）與非必要中繼檔。
3. **增量比對機制**：檢查來源與目的端之檔案大小與修改時間戳（容許 1 秒誤差），僅覆蓋有更新的檔案，大幅縮減複製大型安裝程式（如 200MB 的 WebView2）之 I/O 耗時。
4. **防呆略過邏輯**：若執行環境未偵測到發布基底目錄，或使用者傳入 `--skip-copy` 參數，自動顯示提示並優雅略過，確保非開發機環境或單純本機測試不會報錯。

### 取捨與後續影響 (Consequences / Trade-offs)
- **正面效益**：打包與發布流程全自動化，單項打包（如 `--api-only`）能以秒級完成增量更新，大幅降低人工作業錯誤。
- **邊界限制**：非白名單之附屬檔案（如新加入的非 `.pdf`/`.txt` 說明文件）將不會自動同步至發布目錄，若有新檔案型態需求需擴充白名單集合。
