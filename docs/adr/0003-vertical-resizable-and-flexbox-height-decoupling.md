# 0003: 視窗垂直彈性拉伸 (Vertical Resizable) 與內部 Flexbox 高度徹底解耦

**狀態**: 已採納 (Accepted)  
**日期**: 2026-11-02  

### 決策背景與脈絡
在完成 Per-Monitor DPI 原生渲染修復後，使用者於 150% 桌面縮放環境下測試發現：
1. **視窗高度過長且難以手動調節**：Windows 在 150% 縮放下邏輯高度只有 720px。即便原生層限制了高度，但視窗仍佔滿整個垂直畫面，且 `resizable: false` 導致使用者無法手動將視窗高度縮短至視覺舒適範圍。
2. **底部訊息輸入按鈕遭裁切**：`message-board.vue` 與 `chat-board.vue` 內部大量寫死 `vh` 百分比高度（如 `.chat-container` 寫死 `calc(73.25vh - 18px)`）。在較矮的視窗中，固定高度佔比加上卡片 Header 與控制列，總高度突破 100vh，直接將底部的訊息輸入按鈕（紙飛機、表情、圖片、迴紋針）與狀態列硬生生擠出視窗底部。

### 決策內容與解法
1. **開放垂直方向自由拉伸（Vertical Resizable）**：
   - 寬度鎖死：`minWidth = maxWidth = 490`，維持版面橫向永不破版。
   - 高度開放自由拉伸：`resizable: true`，設定 `minHeight: 500, maxHeight: 850`。
   - 啟動預設高度優化：螢幕邏輯高度小於等於 768px（如 150% 縮放或 1366x768 筆電）時，啟動預設高度主動設為 `600px` ~ `620px`；空間充裕時設為 `740px`。同仁亦可隨時自行拖曳視窗下緣縮短或加長。
2. **前端內部高度全面解耦（Pure Flexbox Layout）**：
   - 摧毀 `message-board.vue` 中寫死的 `73.25vh`、`81.5vh`、`89.5vh`，改為 `height: 100% !important; flex: 1 1 0; min-height: 0;`。
   - 摧毀 `chat-board.vue` 中寫死的 `86.5vh`、`66.5vh`，改為純 flex 自動適應剩餘空間。
   - 保障底部的訊息輸入區（`b-input-group`）與狀態列（`status`）永遠擁有專屬常駐高度，100% 不受中間列表長度影響。

### 取捨與後續影響
- **正面效益**：同仁在 150% 縮放下可隨心所欲縮短視窗高度，且無論視窗縮得多矮，所有按鈕與功能均完美保留、絕不裁切。
- **邊界限制**：視窗最低高度設為 500px，低於此高度將觸發操作系統邊界保護，避免極端縮小時破壞基本可用性。
