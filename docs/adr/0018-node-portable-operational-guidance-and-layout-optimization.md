# 0018. Node 沙盒監管工具介面版面最佳化與維運知識庫內嵌架構

- 日期：2026-11-05
- 狀態：Accepted
- 決策者：pyliu, Antigravity

---

## 1. 背景與問題脈絡 (Context)

智慧控管與監控系統之可攜 Node.js 沙盒監管工具（`tools/node-portable`）在現代桌面解析度（1080p 或以上）及標準視窗（1000x650）下執行時，介面排版面臨以下使用體驗議題：
1. **主安裝分頁（分頁 1）下方大量留白**：在選擇目錄與完成環境狀態偵測後，下方產生約 150px 至 200px 之空白區域，版面略顯空曠。
2. **監控控制台分頁（分頁 2）低密度進程留白**：當主機託管較少受管系統（例如僅 1 至 2 個 PM2 業務進程）時，表格下方至底部狀態列之間留存大面積空白。
3. **現場維運知識斷層**：現場公務同仁或駐點維運人員在進行系統升級、重啟程序或排查日誌時，常因不熟悉 PM2 終端指令或忘記「儲存快照（`pm2 save`）」等關鍵操作，導致主機重啟後服務未如預期復原。

為有效利用畫面空間，並將架構資安特點與日常維運 SOP 在地固化，需於兩個分頁下方內嵌結構化之維運知識指引與指令速查卡片。

---

## 2. 決策方案評估 (Options Considered)

1. **方案 A：雙分頁情境化微卡片知識庫內嵌 (Adopted)**
   - 做法：
     - **分頁 1（安裝部署）**：於操作按鈕列下方配置三欄式「沙盒核心架構與維運特點」卡片，詳細說明「零全域環境污染與資安弱掃隔離」、「專屬終端 `lah-cmd.bat` 與駐留副本」及「開機自啟守護與 Gzip 日誌治理」。
     - **分頁 2（PM2 控制台）**：於受管表格與底部 Toast 之間配置雙欄式「維運指令速查 (CLI Cheat Sheet)」與「狀態守護與 SOP 說明」，提供常用終端命令與快照固化指引。
   - 優點：填滿畫面尷尬空白，版面專業飽滿，且提供最直接易查的現場維運指導。
   - 缺點：需額外維護介面 HTML/CSS 排版。

2. **方案 B：壓縮視窗預設尺寸**
   - 做法：將 Tauri 視窗高度強制限縮至 480px 至 500px。
   - 缺點：導致視窗過小過度擁擠，且日誌彈窗與受管表格可視範圍被嚴重壓縮，無法符合長遠擴充性。

---

## 3. 決策結果 (Decision Outcome)

採納 **方案 A**。

1. **分頁 1 架構指南佈局**：
   - 採 3 欄等寬網格，底色 `#f8fafc` 搭配邊框 `#e2e8f0`。
   - 標題與內文精準闡釋：
     1. `🛡️ 零全域污染沙盒隔離`：不修改系統/使用者 `PATH`，主機命令列 `node -v` 不受影響，日後全域 Node 升級不干擾沙盒。
     2. `💻 專屬終端與駐留副本`：安裝時自動於根目錄產出 `lah-cmd.bat` 與控制台執行檔副本，現場隨點隨維運。
     3. `⚙️ 開機守護與日誌輪替`：`PM2_Portable_Service` 開機自動守護，`pm2-logrotate` 自動以 Gzip 壓縮，預防磁碟爆滿。

2. **分頁 2 維運手冊佈局**：
   - 採雙欄並排卡片，緊接於受管系統表格下方：
     - **左欄（沙盒終端常用指令速查）**：列出 `pm2 list`、`pm2 restart <id|name>`、`pm2 logs <name> --lines 50`、`pm2 save`、`pm2 reloadLogs`，指令均以 `<code>` 標籤美化。
     - **右欄（核心守護機制與維運 SOP）**：重點提醒「更新程式後務必點擊【💾 儲存快照】」、「背景服務每 60 秒主動守護防止解譯器搶佔」與「日誌膨脹時點擊【🗜️ 立即壓縮輪替】即刻釋放空間」。

3. **視覺樣式與自適應原則**：
   - 採用微字級（11.5px 至 12px）與緊湊內距（8px 至 12px），視覺柔和沉穩，不搶奪主操作區視覺焦點。
   - 當受管進程增多時，主視窗支援平滑捲動，指南區塊隨文檔流自然下移，兼顧美觀與機能。

---

## 4. 影響與相容性說明 (Consequences)

- **使用者體驗**：徹底解決視窗留白空曠感，版面更加專業穩重。
- **維運效益**：現場同仁無須翻閱外部手冊即可掌握快照固化與故障自癒 SOP，降低維運失誤率。
- **向下相容性**：純前端介面與樣式擴充，完全不影響既有 Rust 後端邏輯與 PM2 命令執行。
