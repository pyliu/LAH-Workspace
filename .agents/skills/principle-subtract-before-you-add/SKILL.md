# 先做減法，再做加法（Subtract Before You Add）

在演進系統時，請先移除複雜度，再開始建構新東西。預設先做減法。

將「簡化」視為一項持續性的投資。在你離開這段程式碼時，請讓它在維持相同或更小公開介面（Surface）的前提下，比你最初接手時更簡潔且更強大。

- 將「移除」排在「建構」之前
- 先削減再打磨（在投入精力提升品質之前，先把規模縮減到最小必要範圍）
- 針對「實際觀測到的使用情境」進行設計，而非針對憑空臆測的邊界情況（Speculative Edge Cases）
- 除規格明確要求外，不加入預防性的驗證器、解析器或防呆檢查
- 簡化提示詞（Prompts，移除重複的指示與過度繁瑣的範本）
- 當某個參照檔案沒有任何實質新內容時，請直接將其刪除，不要留下空殼（Stub）

> **輸出語言規定**：套用本原則時，所有分析、說明與回覆內容一律使用**台灣繁體中文**。
