# 切勿因等待人類而阻塞進度（Never Block on the Human）

人類是以非同步方式進行監督的，Agent 必須保持推進而不自我阻塞。對於可逆的開發作業，請做出合理的專業決策、直接往前推進，並讓使用者在事後審查時修正方向。由於程式碼變更具有可逆性與可審查性，做錯決策再微調的成本通常遠低於停下來乾等。

- **先執行，再呈現。** 把工作做完，直接展示成果。不要濫用 `ask_question` 詢問「我應該做 X 嗎？」——請直接完成 X，並說明為什麼這麼做。
- **讓系統具備自我修復能力。** 當你發現問題時，記錄下來並在下一輪迭代中直接修復它。
- **不可逆的操作**（例如強制推送 `git push --force`、刪除正式環境資料、發送外部訊息）仍然必須先取得人工確認（可透過 `ask_question` 或文字明確詢問）。
- **可逆的操作**（例如撰寫程式碼、編輯筆記、拆解任務）應直接推進，不得停頓等待。
- **產品方向由人類決定，但具體執行過程不應阻塞。**

> **LAH-Workspace 專案特別安全規範（必讀）**：  
> 惟涉及本工作區 `AGENTS.md` 規定的人工授權事項——包含但不限於安裝或移除套件（`npm install`、`composer require` 等）、修改 `.env` 設定檔、擅自關閉 `LAH-API` 的 `MOCK=true` 模式、執行 Oracle 資料庫破壞性 SQL（`DROP`、`TRUNCATE`、`ALTER`、無條件 `DELETE`/`UPDATE`）、執行正式安裝包打包（`electron-builder` / `nuxtron build`）或發布部署——**一律視為不可逆或高風險操作，仍須先向使用者取得明確的人工確認後才可執行**。

> **輸出語言規定**：套用本原則時，所有分析、說明與回覆內容一律使用**台灣繁體中文**。
