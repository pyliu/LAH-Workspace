# 讓操作具備冪等性（Make Operations Idempotent）

設計各項操作時，請確保無論它們被執行多少次、或前一次執行在哪個時間點中斷，最終都能收斂到正確的狀態。每一個會改變狀態（State-mutating）的操作都應該能回答：「如果這段邏輯連續執行兩次會怎樣？如果前一次執行到一半當機了會怎樣？」

**原因：** 指令、生命週期操作與資料處理迴圈所運作的環境中，當機、重啟與重試都是常態。如果前一次殘留的部分狀態會改變下一次執行的結果，那麼每一次重啟都會演變成一場除錯災難。

**核心概念：** 根據「目前實際存在的狀態」來推導每一步該做什麼，而不是根據「前一次執行原本打算做什麼」。讀取當前狀態、與目標狀態進行比對，並只套用兩者之間的差異（Diff）。以這種方式撰寫的步驟可以安全地重複執行，因為再次執行時會發現已經沒有剩餘工作需要處理。

任何執行過程中留下的產物——例如鎖（Lock）、暫存檔、寫到一半的紀錄或已認領的工作項目——都必須能被下一次執行識別為「已過期（Stale）」。判斷是否過期的依據，必須在「前一次執行可能停在任何一個時間點」的前提下依然成立，而非只在一般正常情況下有效。如果留下了一個下一次執行無法判斷是否過期的標記，每次當機就只能靠人工手動清理。舉例來說，請先寫入暫存路徑再透過重新命名（Rename）原子性地替換到位，或是透過比對產物內容而非建立順序來判斷狀態。

**自我檢視：**
1. 如果這個操作連續執行兩次，會發生什麼事？
2. 如果前一次執行在任何一個可能的位置當機中斷，會發生什麼事？
3. 重新執行是否能收斂到完全相同的最終狀態？

如果以上任何一題的答案是「這取決於前一次留下了什麼狀態」，那麼這項操作就需要補上一個狀態調和（Reconciliation）步驟。
