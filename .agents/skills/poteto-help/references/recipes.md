# 值得複製使用的提示詞範本（Recipes）

請將尖括號 `<...>` 替換為實際的檔案路徑、技能名稱與完成檢查條件。使用自然的口語表達即可。

## 理解與調查（Understand）

- `/poteto-mode 閱讀 <討論串或檔案>，用你自己的話與直白的繁體中文重新陳述底層的真正問題。`
- `/in-your-own-words <冗長或雜亂的需求描述>`
- `/sharpen <你的任務描述>`
- `/poteto-mode 調查為什麼會發生 <症狀>。告訴我目前已知的事實、你根據哪些資料，以及你最合理的假設。先不要修改任何程式碼。`
- `使用 /how 了解 <子系統> 的運作方式，接著用 /why 找出它最近為什麼會壞掉。`
- `/recall 我上週在 <主題> 的工作進度，然後讀取 <議題或檔案>。`
- `/teach 向我解釋為什麼你採用這種實作方式而不是 <另一種方式>？你在這之中做了什麼權衡（Trade-off）？`
- `/poteto-mode 接手這個分支。讀取決策紀錄，確認哪些已經完成並繼續推進，不要重做已經完成的工作。`

## 實作與建置（Build）

- **修復臭蟲**：`/poteto-mode <症狀描述>。先重現問題（repro first），接著修復並驗證。`
- **應用程式臭蟲**：`/poteto-mode 使用 /verify-<應用程式> 重現這個問題。如果在主分支能重現，請修復它並提供驗證證據。`
- **具備快速測試的臭蟲**：`/poteto-mode 先重現 <臭蟲>。如果有低成本的本地測試路徑，請用 /tdd 先寫失敗測試，接著修復並重新執行測試。`
- **新增功能**：`/poteto-mode 新增 <功能行為>。<現有輸出> 必須維持完全一致（Byte-identical）。請同時驗證兩者。`
- **重構程式碼**：`/poteto-mode 將 <程式碼> 移入同一個模組，維持零行為變更（Zero behavior change）。請先記錄目前的輸出，並在重構後證明輸出完全不變。`
- **效能優化**：`/poteto-mode <某項操作> 在 <測試資料> 上耗時 <時間>。請追蹤瓶頸、修復實際量測到的原因，並展示修改前後的數據對比。`

## 設計與規劃（Design and Plan）

- `/poteto-mode 為 <功能> 製作幾個不同方案的原型（Prototype），並提供畫面截圖或驗證結果讓我比較。`
- `/poteto-mode 我們需要 <功能>。請先用 /architect 設計架構，並用原型回答未決問題。在繼續實作前先讓我審查。`
- `/poteto-mode 先寫一份關於我該如何使用 <新套件或模組> 的教學說明，接著用 /teach 向我解釋為什麼它比現有方案更好。`
- `請 /arena 針對這個討論串與我們的作法提供第二意見。`
- `/poteto-mode 將這份設計轉化為實作計畫。拆分成小而可驗證的階段，每個階段都要有明確的驗證步驟。`
- `/poteto-mode 規劃將 <舊函式庫> 遷移至 <目標方案>。拆分成小而可驗證的步驟，結果必須與原本行為完全一致（包含既有邊界行為）。`

## 審查與交付（Review and Ship）

- `/interrogate 以懷疑且嚴格的態度審查整個分支的變更。先不要修改任何東西。除非是真正的臭蟲或迴歸錯誤（Regression），否則不要挑剔瑣碎風格。`（請一併閱讀被駁回的項目說明。）
- `/swarm 針對 <目錄> 下的每個套件或模組平行執行檢查腳本。每個子代理負責一個模組，最後彙整成一份報告。`
- `/poteto-mode 準備提交變更。整理成小而有序的 Commit（依循 AGENTS.md 繁體中文規範），並在說明中附上驗證證據。`
- `/poteto-mode babysit this pr，確保所有檢查通過。`（若僅需查詢狀態：`/poteto-mode 檢查 PR <編號> 是否還有未解決的問題？`）
- `/poteto-mode land the stack。`

## 離開座位與回歸檢視（Away and Back）

- `/poteto-mode 我要先離開座位。請在基於 <基底分支> 的工作樹中完成 <目標>。完成條件為 <檢查條件>。請保留決策紀錄（Decision Log）。如果幾小時後真的卡住，請停下來並寫清楚原因。`
- `/show-me-your-work 幫我快速掌握你剛才完成了哪些工作。`（請優先閱讀報告中的「需注意（Attention）」章節。）
- `/poteto-mode 針對這個佇列執行全自動處理（full autopilot），每個項目彼此獨立。`
- `/poteto-mode 自動處理這些變更並將它們堆疊起來，但先不要推送發布，由我來做最終確認。`
- `/reflect 記錄我們這次學到的經驗，確保下次執行不會重蹈覆轍。`（僅核准真正會改變未來決策的技能修改。）
- `/bro` 用最直白的大白話重新解釋上一段回覆。
