# 體驗優先（Experience First）

當實作上的便利性與使用者的愉悅體驗發生衝突時，請選擇使用者的愉悅體驗。

- 每一個功能、控制項與選項都必須有充分的存在理由
- 少即是多，重質不重量（3 個打磨精緻的功能，勝過 10 個粗糙半成品）
- 定案前先做原型（在用完即丟的 HTML 原型中做設計決策，成本遠低於直接改正式環境程式碼）
- 把細節做到位（轉場動畫、對齊、間距、操作回饋、錯誤狀態）
- 收斂核心流程（每個功能都應該服務於核心工作流程，否則就別擋路）

所謂「使用者」，就是任何消費你工作成果的人。對於 UI 而言，是終端使用者；對於函式庫或內部 API 而言，是匯入並呼叫它的同事；下一位接手維護這段程式碼的工程師也是使用者。請以同樣的標準衡量他們的體驗，並從他們的視角說明變更帶來的影響。

底層基礎架構應該服務於體驗。「基礎優先思維（Foundational Thinking）」決定了工作的**先後順序**，而本原則決定了工作的**最終目標**。
