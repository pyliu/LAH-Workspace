# Swarm（平行子代理群集調度）

> **輸出語言規範**：所有階段規劃、給予工作子代理的任務簡報，以及最終彙整報告，**一律強制使用台灣繁體中文輸出**。

## 啟動準備（Start）

在啟動任何子代理之前，先建立包含四個階段的待辦清單（Todo List）：

1. 定義框架（Frame）
2. 平行展開（Fan out）
3. 彙整結果（Aggregate）
4. 產出報告（Report）

## 階段 A：定義框架（Frame）

1. 明確陳述「完成條件（Done Predicate）」以及本次 Swarm 必須回傳的產出物或報告格式。
2. 選擇展開模式：
   - **切片分割（Partition into slices）**：將大範圍拆成 N 個獨立切片平行處理。
   - **同題競速（Race N workers）**：讓 N 個子代理針對相同簡報平行嘗試。
   - **混合模式（Mix both）**。
   若為競速或混合模式，必須在啟動前先宣告評選規則：`首個通過者勝出（first pass）`、`全數排名（rank all）` 或 `擇優融合（best-of）`。
3. 從 `.agents/rules/pstack-models.md` 的 `swarm workers` 行讀取工作子代理的模型層級；若無該規則檔或設為 `inherit`，則一律使用 `Model: "inherit"`（遵循 Antigravity 預設規範）。若為不同模型間的競速，則預先指定各分支的模型層級。
4. 當工作子代理需要寫入檔案時，務必為每個子代理指定獨立的寫入路徑或使用隔離工作區（`Workspace: "branch"` 或 `"share"`），避免平行寫入衝突。當子代理負責驗證或量測特定 Commit 時，任務簡報必須載明精確的 Commit SHA；若是效能或數據量測簡報，還必須載明量測方法（樣本數、單一樣本定義、執行順序），並要求子代理在結果中一併記錄。

## 階段 B：平行展開（Fan out）

在單一 `invoke_subagent` 呼叫的 `Subagents` 陣列中，一次平行啟動所有 N 個工作子代理（唯讀檢查與探索設定 `TypeName: "research"`，需要修改或執行指令則設定 `TypeName: "self"`，並填入步驟 3 決定的 `Model`）。

每份子代理任務簡報（`Prompt`）都必須是**自給自足、可獨立執行的**。簡報中必須包含：目標、範圍、負責的確切切片或競速分支、如何驗證，以及回報格式。子代理回報必須使用 `PASS`（通過）、`ISSUES`（發現問題）或 `BLOCKED`（受阻）標頭並附上具體證據。若子代理能證明存在缺陷，必須回報 `ISSUES` 並列出所有能證明的問題（而非只列第一個）。

若某個子代理中途失敗或無回應，請以剩餘的 N-1 個結果繼續推進，並在報告中明確註記。

## 階段 C：彙整結果（Aggregate）

收集所有工作子代理透過訊息回傳的終端結果。若有子代理未依簡報要求記錄 Commit SHA 與量測方法，請捨棄該結果並重新啟動一次該子代理；若第二次仍缺漏，則記錄為「缺口（Gap）」。**缺口絕不可算作通過（Pass）。** 針對覆蓋率檢查，每個必要的切片都必須有結果；針對競速模式，則套用事先宣告的評選規則（`first pass`、`rank all` 或 `best-of`）。請勿將子代理的原始冗長輸出直接傾倒給使用者。

## 階段 D：產出報告（Report）

在對話中回傳一份整合後的繁體中文總結報告，包含：結果總表、單行問題摘要、缺口或失敗的子代理說明，以及（若使用競速模式）所套用的評選規則與勝出理由。
