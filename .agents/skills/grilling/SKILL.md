# 深度決策盤問 (Grilling)

持續且深入地盤問使用者，直到雙方達成完全一致的理解。  
將所有待決策事項組織為**決策樹（Design Tree）**：每個主決策都會分支出依賴於它的子決策。

---

## 核心流程

### 1. 輪次推進（Rounds & Frontier）
以**輪次（Rounds）**為單位推展決策樹。  
**前沿（Frontier）**代表所有「先決條件已底定、可以立即詢問」的決策問題，切勿臆測尚未得知答案的問題。

每一輪次同時詢問當前 Frontier 的所有問題：為每個問題編號，並提供你的**推薦答案（以 `(推薦)` 標示）**。  
等待使用者回覆後，才進入下一輪次。

格式範例：

```markdown
? **Q1** - **<問題標題>**: <問題說明內文，可包含多段落與選項列表>

?? **(推薦)** <你的具體推薦答案與簡短原因>

---

? **Q2** - **<問題標題>**: <問題說明內文，可包含多段落與選項列表>

?? **(推薦)** <你的具體推薦答案與簡短原因>
```

> **提示**：問題的提問方式應設計成使用者若回答「好」或「同意」，即代表接受你的推薦選項。

### 2. 重算前沿（Recomputing the Frontier）
使用者在每輪回覆後，會確定某些決策，並將決策樹的前沿往外推展，解鎖後續依賴的子問題。  
重新計算 Frontier 並提出下一輪。若某個問題的答案仍取決於本輪中其他尚未決定的事項，請保留到後續輪次，切勿提前詢問。

### 3. Agent 查事實，使用者做決策（Facts vs Decisions）
- **查證事實（Finding Facts）是 Agent 的責任**：  
  當 Frontier 的問題需要環境資訊（程式碼、檔案系統、API 介面、資料庫 Schema 等）時，Agent 應自行使用工具查明，**嚴禁詢問使用者你自己就能查到的事實**。
- **決定方向（Decisions）是使用者的特權**：  
  列出選項、利弊與推薦方案，交給使用者裁定。

### 4. 結束條件
當 Frontier 為空時代表盤問完成：決策樹的每個分支皆已走過，沒有任何隱含假設被遺漏。  
在使用者正式確認「理解已達成一致」之前，切勿直接動工寫程式碼。
