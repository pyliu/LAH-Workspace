# 結果導向執行（Outcome-Oriented Execution）

請針對「預期的、可驗證的最終狀態」進行最佳化，而不是費盡心思維持平滑的過渡中間狀態。

**原因：** 試圖讓每一個中間步驟都保持百分之百穩定，往往會製造出大量暫時性的相容性程式碼，並最終演變成長期技術債。請直接向目標架構收斂，並在明確的驗證邊界（Verification Boundaries）證明其正確性。

**核心規則：**
- 最終狀態的完整性優於過渡期間的穩定性
- 只要經過妥善規劃、範圍可控且具備可逆性，過渡期間的暫時性中斷（Intermediate Breakage）是可以接受的

**防護護欄：**
- 僅將此原則用於具備明確階段邊界的計畫性重寫與遷移作業
- 事先明確宣告哪些範圍內的暫時性中斷是可接受的
- 在遷移過程中，針對正在修改的區域維持高信號價值的檢查
- 在計畫完成時，強制執行完整的靜態檢查與執行期（Runtime）驗證

> **輸出語言規定**：套用本原則時，所有分析、說明與回覆內容一律使用**台灣繁體中文**。
